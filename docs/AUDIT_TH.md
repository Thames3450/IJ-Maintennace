# ผลปรับปรุง IJ Maintenance v13.11.2

ตรวจจากโค้ด v13.5 ภาพหน้าจอเดิม และ schema จริงของ Supabase เมื่อ 2 ตุลาคม 2026 แล้วปรับตามข้อเสนอแนะเรื่องมาตรฐาน PM และตัวหนังสือ

## สิ่งที่เปลี่ยน

| จุดเดิม | ผลใน v13.6 |
|---|---|
| PM มีเพียงชื่อแผนและปุ่มส่งเข้า TPM | PM มีใบมาตรฐาน ตารางรอบ เริ่มงาน บันทึกผล ทำต่อ ปิดงาน และประวัติของตัวเอง |
| ไม่มีวิธีทำและเกณฑ์รายข้อในหน้า PM | แม่แบบ 5 รอบ รวม 29 รายการ มีวิธีทำ เกณฑ์ผ่าน เครื่องมือ และช่องปรับค่าจากคู่มือ |
| ไม่มีการควบคุมฉบับมาตรฐาน | ร่าง / รับรอง / Revision ใหม่ และ snapshot ของฉบับที่ใช้ในใบงาน |
| ไม่มีผล PM รายข้อ | บันทึกผล ค่าจริง หมายเหตุ สิ่งที่แก้ อะไหล่ และการคืนเครื่อง |
| งานตามรอบไปสร้างรายการ TPM | ตารางและผล PM บันทึกใน `ij_pm_standards` / `ij_pm_orders` และ RPC ของ PM |
| ปิดงานอาจเกิดข้อมูลบางส่วนเมื่อคำขอต่อกันล้มเหลว | ปิด PM และสร้างรอบถัดไปใน transaction เดียว พร้อมการป้องกันกดซ้ำ |
| PM Compliance นับทุกงานที่ปิดเป็นตรงรอบ | นับงานที่ปิดภายในวันครบกำหนดเป็นตรงรอบ งานช้าแสดงว่าทำเสร็จแยกจากตรงกำหนด |
| ตัวอักษรหลายส่วน 7–11px | เนื้อหา 16px ข้อความรองขั้นต่ำ 14px หัวข้อ 24–30px พร้อมระยะห่างใหม่ |
| เมนูหลักอังกฤษและคำอธิบายซ้ำยาว | ไทยเป็นชื่อหลัก แยกทางลัด PM / TPM และลดข้อความซ้ำ |
| เมื่อตัวหนังสือใหญ่ ปุ่มทำให้มือถือย่อทั้งหน้า | ปรับตาราง ปุ่มสองภาษา ตัวกรอง และการ์ดให้พอดีกับ viewport 390px |
| ปฏิทินเริ่มจากเดือนของวันจันทร์ ทำให้เดือนผิดเมื่อสัปดาห์คร่อมเดือน | เริ่มแสดงเดือนปัจจุบันและคงวันที่เลือกให้ตรงงาน |
| หน้าต่างบางส่วนถูกจำกัดโดย layout ของหน้าเว็บ และการพิมพ์ PM ซ่อนเอกสารด้วย | ให้หน้าต่างแสดงผ่าน portal เหนือหน้าเว็บ พิมพ์เฉพาะเอกสาร และคงพื้นที่ปุ่มบนมือถือ |
| ปฏิทินมือถือมีความกว้างขั้นต่ำ 560px | เห็นครบ 7 วันในความกว้างมือถือ ใช้จุดบอกงานและเปิดรายละเอียดวันที่เลือก |

## หลักฐานการตรวจ

- `npm test` ผ่าน 16 กรณี
- `npm run test:database` ผ่าน 16 กรณีบน PostgreSQL ภายในเครื่อง (PGlite) ใช้ migration, RLS, trigger และ RPC จริง
- `npm run test:browser` ผ่าน 25 กรณีใน Chromium พร้อมจำลอง Supabase API
- ตรวจภาพและขนาดตัวอักษรที่แสดงจริงทั้ง 14 หน้า บนจอ 1280px และมือถือจำลอง 390px ตรวจไม่มีข้อความเล็กกว่า 14px และไม่มีการเลื่อนทั้งหน้าไปด้านข้าง
- ตรวจการทำ PM, บันทึกค้างไว้ทำต่อ, กรอกค่า 0, รับรองมาตรฐาน, จัดรอบ, การบันทึกล้มเหลวแล้วลองใหม่ และยืนยันว่า PM ไม่เขียนรายการ TPM
- ผลตรวจฐานข้อมูลป้องกันผลนอกเกณฑ์ การปิดงานไม่ครบ ทุกข้อ N/A การแก้ snapshot การแก้ผลที่ปิดแล้ว และการลบรายการ
- API จริงอ่านตาราง PM ได้และเรียก RPC ด้วยรหัสใบงานที่ไม่มีแล้วถูกปฏิเสธตามที่คาด โดยไม่เขียนข้อมูลทดสอบลงตารางใช้งาน
- Supabase Security Advisor ไม่พบรายการแจ้งเตือนเกี่ยวกับตารางและฟังก์ชัน PM ใหม่ในการตรวจครั้งนี้

ผลแบบอ่านด้วยโปรแกรม: `browser-test-results.json`, `pm-database-test-results.json`, `pm-api-smoke-results.json`
ภาพหน้าจอใหม่: `screenshots/desktop/`, `screenshots/mobile/`
ภาพก่อนปรับ: `screenshots/before/`

## การติดตั้งฐานข้อมูล

Migration `20261002134634_ij_pm_standards_and_orders.sql` ติดตั้งในโครงการ Supabase ที่ระบุในโค้ดแล้ว เพิ่มเฉพาะส่วน PM ใหม่ ตารางมาตรฐานและใบงานจริงยังว่าง ไม่มีการเพิ่มมาตรฐานที่อ้างว่ารับรองแล้วหรือใบงานทดสอบให้ผู้ใช้

ไฟล์เว็บที่ส่งเป็น Source และ `dist/` สำหรับนำขึ้น GitHub Pages/โฮสต์เดิม ยังไม่มีการเผยแพร่ frontend ไปยังเว็บไซต์จริงในการปรับครั้งนี้

## ขอบเขตที่ยังต้องใช้งานจริง

แม่แบบ PM ต้องทวนสอบตามคู่มือรุ่นเครื่อง รอบ เวลา Spec และขอบเขตงานของโรงงานก่อนรับรอง ข้อมูลผู้ทวนสอบในโหมดไม่ Login เป็นชื่อที่ผู้ใช้บันทึก ไม่มีการยืนยันตัวตนด้วยลายเซ็นดิจิทัล

การตรวจมือถือเป็น Chromium จำลอง ยังไม่ได้ทดสอบบน Safari/iPhone จริง การพิมพ์มาตรฐานและผลตรวจด้วย browser ใช้รูปแบบเอกสารที่แยกจากหน้าระบบ ส่วนฟังก์ชันรูปของ Inspection/Defect ใช้ workflow เดิมที่ตรวจใน v13.5

รายละเอียดการตรวจรอบก่อนและข้อจำกัดของ workflow เดิมอยู่ใน `AUDIT_v13.5_TH.md` ข้อ “เชื่อม PM Due เข้า TPM” จากรายงานรอบก่อนถูกแทนด้วยระบบ PM แยกใน v13.6


## v13.7 — รูปภาพและ QR เครื่องจักร (3 ตุลาคม 2026)

- ศูนย์เครื่องจักรพิมพ์ทีละเครื่องหรือหลายเครื่องที่ค้นหา/กรองไว้ เลือกย่อยได้ ตรวจ URL เว็บจริงและป้องกัน localhost ก่อนพิมพ์ ป้ายเลขเครื่องใหญ่ มี quiet zone 4 modules และ QR 45mm ในโหมดพิมพ์
- ทดสอบถอดรหัส QR จาก PNG ด้วย jsQR ยืนยัน machine ID จริงใน fixture ตรวจพิมพ์ซ่อน controls มือถือไม่ล้นจอ และรูปแกลเลอรีเข้า preview

## v13.8 — งานติดตามและข้อความ TPM (4 ตุลาคม 2026)
- ปรับหน้างานติดตามตามภาพผู้ใช้: สรุปงานค้าง/เกินกำหนด/รอตรวจยืนยัน/ปิดแล้ว ค้นหาเครื่อง ปัญหา ผู้รับผิดชอบได้ แสดง next action บนการ์ด
- ลดรายละเอียดซ้ำบนการ์ด เหลือปัญหา ผู้รับผิดชอบ วันกำหนด ข้อกำหนดที่เกี่ยวข้อง รายละเอียดแผน/ผลและรูปเปิดได้ใน details
- ฟอร์มภาษาไทยแบ่งเป็นวางแผน ผลจริง ตรวจยืนยัน ไม่เปลี่ยนรูปแบบข้อมูลเดิมและเงื่อนไขปิดงาน เมื่อ API ล้มเหลวยังคงข้อมูลในฟอร์ม
- สาเหตุข้อความปุ่ม TPM ล้นกรอบ: container เดิม height 48px แต่ button ต้องรองรับ font 15px + subtitle 14px และ padding แก้เป็นความสูงอัตโนมัติ min-height 64px และจัดข้อความสองบรรทัดภายใน
- ตรวจข้อความในปุ่มเดือน/สัปดาห์/รายการให้อยู่ภายในขอบ button และ parent ที่ความกว้าง 390 / 768 / 1280 / 1693px พร้อมปรับ wrap ชื่อแผน งาน และข้อมูลยาว
- ทดสอบ browser ทั้ง 14 เมนูและ flow เดิม รวมตัวกรอง/ค้นหา/รายละเอียด/ข้อมูลยาว/failed save/new editor ไม่สร้างข้อมูลทดสอบในฐานจริง
- ไม่เปลี่ยน schema และยังไม่ได้ deploy เว็บ ผู้ใช้นำ source/dist ฉบับนี้ขึ้นโฮสต์เดิม

## v13.11 — ปิดงานที่เชื่อมกัน และลดการกรอกซ้ำ (4 ตุลาคม 2026)

- สาเหตุ: completeJob เดิม upsert ผล TPM/เปลี่ยนสถานะ job แต่ไม่เขียน source_finding_id กลับไปยังงานติดตาม ฟอร์มติดตามเดิมแสดงทั้งสามขั้นพร้อมกัน ผู้ใช้ต้องกรอกผลสองครั้ง
- เพิ่ม RPC SECURITY INVOKER สำหรับเริ่ม TPM ปิด TPM และอัปเดตงานติดตาม ใช้ row lock และ transaction เดียว ตรวจสิทธิ์และจำนวนแถวที่เขียน เมื่อผลต้นทางบันทึกไม่ได้ ผล TPM และสถานะ job ย้อนกลับด้วย
- ปิดต้นทางเมื่อ TPM ครบ มีผลจริงและผลตรวจยืนยัน และไม่มี TPM อื่นที่ยังเปิดอยู่ งานบางส่วน/ต้องติดตามต่อยังเปิด ไม่สร้าง finding ซ้ำถ้ามีต้นทางอยู่ รวมหลักฐานจากหลายงานที่เชื่อมไว้ ไม่ปิดรายการที่ไม่เกี่ยวข้อง
- ใช้ completion attempt ID เพื่อ retry ไม่เปลี่ยนวันปิดหรือเขียนงานที่ปิดแล้วซ้ำ
- งานติดตามมีปุ่มอัปเดตและปิดงานแยกกัน รายละเอียดเพิ่มเติมยุบไว้ งานที่มีแผนเปิด TPM เดิม รุ่นก่อนดึงผลเดิมจาก execution ให้กรอกเพียงผลตรวจยืนยันที่ขาด
- ลบจากรายการ 8 ประเภท ผ่านหน้าต่างระบุทุกรายการและ checkbox ยืนยัน เก็บต้นฉบับกับไฟล์รูปไว้ ใช้ deletion markers ไม่เพิ่มการลบ cascade และไม่เปลี่ยนข้อมูลซ่อม/อะไหล่ใน MPR ต้นทาง ซ่อนในสถิติและ timeline ของ IJ ด้วย
- ลบงานทั้งแผนแสดงทุกงานจริง แม้ตัวกรองเครื่องจะซ่อนบางงานไว้ การลบแถวแผนหรือข้อ PM ที่กำลังร่างก็ต้องยืนยันก่อน
- แก้การล้นของปุ่มบนมือถือในรายการปรับปรุงเมื่อมีปุ่มลบ และป้องกัน toast เดิมทับปุ่มใน modal

## v13.11.2 — รูปผลตรวจไม่ขึ้น

- รูปของผลตรวจ 230T-5 ทั้งสองไฟล์ยังอยู่ใน Storage จริง แต่ bucket เป็น private ลิงก์ public ที่หน้าผลตรวจเดิมใช้จึงได้ HTTP 400
- เปลี่ยนหน้าผลตรวจ จุดผิดปกติ และงานติดตามให้ใช้ตัวสร้าง signed URL ร่วมกัน จัดกลุ่มตาม bucket แบ่งครั้งละไม่เกิน 100 paths และไม่ใช้ public URL เป็นทางเลือกเมื่อ signing ล้มเหลว ตรวจ error รายไฟล์ด้วย รูปอื่นที่โหลดได้ยังแสดงอยู่
- รูปใหม่เก็บ bucket/path และ public_url เป็น null ใช้โครงสร้างเดิม ไม่มี migration และไม่แก้ metadata หรือไฟล์รูปเดิม
- รูปที่โหลดไม่ได้ลองสร้างลิงก์ใหม่อัตโนมัติหนึ่งครั้ง แล้วแสดงปุ่มลองโหลดใหม่ แทนการปล่อยไอคอนรูปเสียหรือโหลดวนซ้ำ หน้าผลตรวจโหลด metadata ใหม่ได้โดยไม่ต้องกรอกผลซ้ำ
- ทดสอบ logic 24 กรณี, PM PostgreSQL 16 กรณี, workflow PostgreSQL 18 กรณี และ build ผ่านด้วย Node 20.20.2 / npm 10.8.2
- Browser 47 กรณีผ่าน: API จำลองปฏิเสธ public URL, ตรวจ naturalWidth หลัง decode สำหรับรูปเก่า รูปใหม่ และทั้งสามหน้า รวม partial signing error, expired URL, manual retry, metadata retry และความกว้างมือถือ 320/390/430px
- ตรวจ UI รุ่นที่แก้กับ API และรูปจริงของ 230T-5 ผ่านตัวส่งต่อคำขออ่านใน Node: โหลดรูป JPEG ทั้งสองเป็น 3024 × 4032 ได้ ไม่มี React error ทุกคำขอเขียนถูกบล็อก ยกเว้น POST สร้างลิงก์อ่านรูป ไม่มีการเขียนข้อมูลจริง ผลอยู่ใน photo-production-smoke.json
- ตรวจ advisors พบรายการเดิมสองรายการ ไม่มีการเปลี่ยน bucket, RLS, permissions หรือ SQL ในรุ่นนี้ หน้าเว็บจริงต้องอัปเดตด้วยไฟล์ที่ส่ง
