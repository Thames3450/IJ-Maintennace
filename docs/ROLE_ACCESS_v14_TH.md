# IJ Maintenance v14.1 — เข้าระบบด้วยรหัสพนักงาน

กรอกรหัสพนักงานช่องเดียว ไม่ต้องใช้อีเมลหรือรหัสผ่าน หากไม่มีชื่อ ระบบให้ลงทะเบียนชื่อและตำแหน่ง แล้วรอ Engineer อนุมัติ

| ตำแหน่ง | การใช้งาน |
|---|---|
| Engineer / Admin | ทุกเมนู ตรวจเครื่อง ทำ PM/TPM บันทึกผล รับและมอบหมายงาน ยืนยัน/อนุมัติแผน จัดการผู้ใช้ |
| ช่าง | ตรวจเครื่อง ทำ TPM ที่รับมอบหมาย ทำ PM บันทึกผล ติดตามปัญหาและอะไหล่ |
| ผู้จัดการ | ภาพรวม สุขภาพเครื่อง Loss Time KPI ประวัติ ปฏิทิน PM/TPM และอนุมัติ/ส่งกลับแผน |
| Production / Planning | ภาพรวมรายเครื่อง สุขภาพเครื่อง ประวัติ ปฏิทิน และยืนยันช่วงหยุด/เสนอเลื่อน |

- 680470 — อภิวุฒิ ขวัญเมืองคูณ — Engineer
- 680896 — รัฐธรรมนูญ เดชทะสอน — Engineer
- Engineer ทั้งสองชื่อเลือกเป็นผู้รับผิดชอบงานได้
- ไม่มีขั้นตอน Production รับเครื่องกลับ
- งานที่ผูก TPM บันทึกผลครั้งเดียวและส่งกลับงานติดตามตามผลตรวจยืนยัน

## ติดตั้งรุ่นนี้ (ต้องทำทั้งเว็บและฐานข้อมูล)

ชุดนี้เป็นไฟล์พร้อมติดตั้ง ยังไม่ได้เผยแพร่เว็บหรือเปิด migration v14.1 บนฐานใช้งานจริง ส่วนฐาน v14.0 ของโครงการเดิมมีแล้ว

1. แตก ZIP แล้วเปิด `ij-system-v14.1` คัดลอกไฟล์ภายในทั้งหมดทับ root repository เดิม รวม `.github` และ `tests` แล้ว Commit/Push
2. รอ GitHub Actions build/deploy ผ่าน ในช่วงอัปเดตให้งดบันทึกงาน
3. เปิด Supabase SQL Editor โครงการ MPR เดิม แล้วรัน **เพียงครั้งเดียว** ไฟล์ `supabase/migrations/20261004161427_ij_employee_sessions_and_permissions.sql` ทั้งไฟล์ มี BEGIN/COMMIT เพื่อให้ติดตั้งครบพร้อมกัน อย่ารัน migration v14.0 ซ้ำ
4. รีเฟรชเว็บ เข้าด้วย 680470 หรือ 680896 ตรวจชื่อและ Engineer แล้วทดสอบเปิดปฏิทิน รูปผลตรวจ และเมนูผู้ใช้และสิทธิ์
5. ทดสอบลงทะเบียนด้วยรหัสพนักงานจริงของผู้ใช้ใหม่ → Engineer เปิดผู้ใช้และสิทธิ์ → ตรวจตำแหน่งและอนุมัติ → ผู้สมัครกดตรวจสอบสถานะ

เว็บ v14.1 ต้องใช้ SQL v14.1 คู่กัน เว็บรุ่นเก่าจะเข้าใช้งานไม่ได้หลังเปิดกฎใหม่ จึงต้องเตรียมเว็บรุ่นใหม่ก่อน ไม่มีการลบ/ปิดงานเก่าโดย migration นี้

## สิ่งที่เพิ่มจาก v14.0

- เซสชันอายุ 12 ชั่วโมง ออกจากระบบแล้วเพิกถอนเซสชัน และใช้สิทธิ์ล่าสุดจากฐานข้อมูล
- ตรวจสิทธิ์ฐานข้อมูลสำหรับช่องทาง anonymous ของเว็บ IJ รวมการอ่านรูปและบันทึกงาน
- Engineer ยืนยันช่วงหยุดและอนุมัติแผนได้ ผู้จัดการรอการยืนยันช่วงหยุดก่อนอนุมัติ
- ป้องกันลดสิทธิ์/ปิด Engineer คนสุดท้าย และป้องกันอนุมัติคำขอเดิมซ้ำ
- ผู้จัดการและ Production เปิดหน้าภาพรวมเป็นหน้าแรก ปฏิทินแสดง PM ร่วมกับ TPM
- ปุ่มแนบ/ถ่ายรูป ลบรูปแบบยืนยัน และหน้ามือถือคงอยู่

## ขอบเขตและการตรวจสอบ

การใช้รหัสพนักงานอย่างเดียวไม่สามารถป้องกันคนที่รู้รหัสผู้อื่นสวมสิทธิ์ได้ ตามข้อกำหนดนี้ไม่มี PIN/OTP เพิ่ม

ทดสอบหน้าเว็บด้วย Chromium และ API จำลอง รวมการทำงานเดิม/สิทธิ์ตำแหน่ง และทดสอบ SQL จริงใน PostgreSQL ภายในเครื่อง (PGlite) โดยไม่แก้ข้อมูลการทำงานจริง ยังไม่ได้ทดสอบเซสชันใหม่กับ Storage API ของโครงการจริงหลังติดตั้ง จึงต้องตรวจเปิดรูปและแนบรูปด้วยบัญชีจริงตามข้อ 4 ก่อนให้ทีมใช้

- `npm ci` → `npm test`
- `npm run test:database` → `npm run test:workflow-database` → `npm run test:access-database`
- `npx playwright install chromium` → `npm run test:browser`
- `npm run build` สร้างไฟล์ใน `dist` สำหรับ static hosting

ไฟล์ผลทดสอบอยู่ใน `docs` แม่แบบ PM ต้องตรวจรับตามรุ่นเครื่องและคู่มือผู้ผลิตก่อนนำไปใช้จริง
