# IJ Maintenance v13.11 — ปิด TPM และงานติดตามในครั้งเดียว

PM มีใบมาตรฐาน ตารางรอบงาน และประวัติผลรายข้อของตัวเอง มีแม่แบบ 5 รอบ: สัปดาห์ เดือน 3 เดือน 6 เดือน และปี เก็บ revision ของมาตรฐานไว้ในใบงาน และสร้างรอบถัดไปได้เมื่อปิด PM

ปรับตัวอักษรและการจัดวางทุกเมนู: เนื้อหา 16px ข้อความรองอย่างน้อย 14px หัวข้อ 24–30px ภาษาไทยเป็นหลัก รองรับคอมพิวเตอร์และมือถือโดยไม่ย่อทั้งหน้า

รุ่นนี้แก้การกรอกซ้ำ: ผล TPM ส่งกลับไปงานติดตามต้นทางพร้อมกัน แยกปุ่มอัปเดตงาน / บันทึกผลและปิดงาน และเพิ่มการลบรายการที่ต้องยืนยันก่อน

## เริ่มใช้งาน

1. แตก ZIP และเปิดโฟลเดอร์ `ij-system-v13.11`
2. ใช้ Node.js 20 ขึ้นไป แล้วรัน `npm ci`
3. รัน `npm run dev` เพื่อเปิดเครื่องพัฒนา หรือ `npm run build` เพื่อสร้างเว็บ
4. สำหรับ GitHub Pages อัปโหลดไฟล์ภายในโฟลเดอร์นี้เป็น root ของ repository และใช้ workflow ที่ให้มา
5. สำหรับโฮสต์ static ให้นำ **ไฟล์ภายใน `dist/` ทั้งหมด** ขึ้นโฮสต์ โดยคงโครงสร้าง assets และ icons

ไฟล์ `.env.example` แสดงตัวแปรที่รองรับ คงโหมดเปิดใช้โดยไม่ Login และใช้ publishable key ตามโครงการเดิม

## ฐานข้อมูล PM

ติดตั้ง migration `supabase/migrations/20261002134634_ij_pm_standards_and_orders.sql` ใน Supabase โครงการที่เว็บเชื่อมอยู่ **เพียงครั้งเดียว**

**ฐานข้อมูลโครงการที่ระบุในโค้ดชุดนี้ติดตั้งแล้วเมื่อ 2 ตุลาคม 2026** ไม่ต้องรันซ้ำ การติดตั้งเพิ่มตาราง `ij_pm_standards`, `ij_pm_orders` และ RPC สำหรับบันทึกมาตรฐาน สร้างรอบ เริ่มงาน และปิด PM รายละเอียดอยู่ใน `docs/PM_STANDARD_TH.md`

เมื่อย้ายไปโครงการอื่น ต้องมีฐาน MPR/IJ เดิมที่เข้ากันได้และติดตั้ง migration PM ไฟล์ SQL เวอร์ชันเก่าเป็นข้อมูลอ้างอิง ไม่ใช่ขั้นตอนสร้างฐานข้อมูลทั้งหมดจากศูนย์

## รูปภาพและ QR เครื่องจักร (v13.7)

งานตรวจสภาพและแจ้งจุดผิดปกติมีปุ่มแยก ถ่ายรูป / เลือกจากเครื่อง รองรับหลายรูปในปุ่มเลือกไฟล์ โดยใช้ข้อจำกัดเดิม (ตรวจสภาพ 3 รูปต่อจุด / Defect 4 รูป รูปละไม่เกิน 10 MB)

เปิดศูนย์ข้อมูลเครื่องจักร > พิมพ์ QR ของแต่ละเครื่อง หรือพิมพ์เครื่องที่แสดง > ตรวจ URL เว็บจริง > เลือกเครื่อง > พิมพ์ / บันทึก PDF ป้ายมีเลขเครื่องและ QR ที่เปิด #history?machine=รหัสเครื่อง โดยตรง URL ต้องเข้าถึงได้จากมือถือและรวม path โครงการ GitHub Pages ถ้ามี ไม่ใช้ localhost สแกนทดสอบหนึ่งป้ายก่อนพิมพ์ทั้งหมด ฟังก์ชันสร้าง QR ทำงานในเว็บ ไม่ส่ง URL ไปบริการสร้าง QR ภายนอก

ไฟล์นี้ยังต้องนำขึ้นโฮสต์เดิมก่อนใช้งานจริง ไม่ต้องเปลี่ยนฐานข้อมูลเพิ่มสำหรับรูปและ QR

## งานติดตามและปฏิทิน TPM (v13.8)

หน้างานติดตามแสดงสรุป 4 กลุ่ม กดดูงานค้าง/เกินกำหนด/รอตรวจยืนยัน/ปิดแล้ว ค้นหาเครื่อง ปัญหา หรือผู้รับผิดชอบได้ การ์ดแสดงสิ่งที่ต้องทำต่อ รายละเอียดแผน ผลจริง และรูปเปิดดูได้ด้วย “รายละเอียดแผนและผล” ฟอร์มแบ่ง 3 ส่วน วางแผน / สิ่งที่ทำจริง / ผลตรวจยืนยัน กรอกเฉพาะส่วนที่ถึงขั้นตอนแล้ว การปิดงานยังต้องมีผู้รับผิดชอบ วิธีแก้ไข ผลดำเนินการจริง และผลตรวจยืนยัน

แก้ปุ่มเดือน/สัปดาห์/รายการใน TPM ให้ขยายตามความสูงข้อความสองบรรทัด รวมถึงการตัดบรรทัดชื่อแผนและงานยาว ไม่ต้องรัน SQL เพิ่มสำหรับ v13.8 ต้องนำไฟล์ขึ้นโฮสต์เดิมก่อนใช้งาน

## ภาษาไทยรายการตรวจสภาพ (v13.9)

เพิ่มคำแปลภาษาไทยคู่กับชื่ออังกฤษสำหรับจุดตรวจเดิมของ IJ ทั้ง 12 ข้อ และวิธีตรวจทั้ง 10 แบบ แสดงในฟอร์มตรวจและผลย้อนหลัง เปลี่ยนเฉพาะข้อความที่แสดง ไม่เปลี่ยนรหัส template/item หรือชื่อ snapshot ที่บันทึกเดิม ข้อความที่มีภาษาไทยอยู่แล้วไม่เติมซ้ำ ชื่อที่ยังไม่มีคำแปลในพจนานุกรมจะแสดงต้นฉบับ

## มือถือและปฏิทิน TPM (v13.10)

แก้ footer ฟอร์มสร้างแผน/ปิดงานให้สรุปข้อมูลอยู่แถวเต็ม แล้ววางปุ่มสองปุ่มแถวถัดไป พร้อมข้อความไทยและอังกฤษคนละบรรทัด รองรับขนาด 320/390/430px และกำหนด text-size-adjust 100% เพื่อไม่ให้ browser ขยายข้อความบางส่วนโดยอัตโนมัติ

เมื่อเปิด TPM บนมือถือเริ่มที่รายการงานตามวัน แสดงชื่อเครื่องและงานเต็มบรรทัด กดวันที่เพื่อดูรายละเอียดงานด้านล่าง มีช่องเลือกวันโดยตรง และสลับเดือน/สัปดาห์/รายการได้ มุมมองเดือนย่อความสูงและแสดงจำนวนงานแทนจุดสี ไม่มี SQL เพิ่มและยังต้องนำไฟล์ขึ้นโฮสต์เดิม

## การปิดงานและการลบ (v13.11)

- ตรวจเครื่องแล้วพบ Watch/Abnormal จะสร้างจุดผิดปกติและงานติดตามรายการเดียวกัน
- แก้ไขทันทีจากงานติดตาม: กด **อัปเดตงาน** เพื่อบันทึกสถานะ หรือ **บันทึกผลและปิดงาน** เพื่อกรอกผู้รับผิดชอบ ผลที่ทำจริง และผลตรวจยืนยัน โดยไม่จำเป็นต้องเข้าแผน TPM
- นัดทำผ่าน TPM: เปิด **เพิ่มเติม > นำเข้าแผน TPM** จากงานติดตาม กรอกผู้รับผิดชอบและแผน เมื่อมีแผนแล้วการ์ดจะมี **ทำงานผ่าน TPM** พาไปงานเดิม
- เมื่อปิด TPM ที่เชื่อมไว้ ช่อง **ปิดงานติดตามพร้อม TPM** เลือกไว้ให้ กรอกผลแก้ไขและผลตรวจยืนยันครั้งเดียว ระบบบันทึก TPM และปิดงานติดตามพร้อมกัน หากเลือกทำบางส่วน ต้องติดตามต่อ หรือยังมี TPM อื่นที่ยังไม่เสร็จ งานติดตามจะยังเปิดอยู่
- TPM รุ่นก่อนที่ปิดแล้วแต่ต้นทางยังเปิดอยู่: ระบบดึงผลเดิมมาในฟอร์มปิดงานติดตาม ให้ตรวจสอบและกรอกผลยืนยันได้เลย ไม่ปิดข้อมูลเก่าให้อัตโนมัติโดยไม่มีการยืนยัน
- ปุ่มลบมีในงานติดตาม/จุดผิดปกติ TPM ทั้งงานหรือทั้งแผน ผลตรวจ รายการปรับปรุง คำขออะไหล่ รายการซ่อม รอบ PM และมาตรฐาน PM หน้ายืนยันแสดงทุกรายการและต้องติ๊ก **ฉันตรวจสอบรายการที่จะลบแล้ว** ก่อนกดลบ
- การลบเป็นการนำออกจากหน้าระบบ IJ รวมถึงสถิติและประวัติเครื่อง โดยเก็บข้อมูลและไฟล์รูปเดิมไว้ รายการที่เชื่อมกันไม่ถูกลบต่อเนื่อง เช่น ลบผลตรวจแล้วงานติดตามยังอยู่ หรือลบ TPM แล้วงานติดตามต้นทางยังอยู่ ข้อมูลซ่อมและคำขออะไหล่ในระบบ MPR ต้นทางไม่ถูกลบ

ฐานข้อมูลโครงการในโค้ดติดตั้ง `supabase/migrations/20261004104312_ij_tpm_followup_and_confirmed_deletion.sql` แล้วเมื่อ **4 ตุลาคม 2026** ไม่ต้องรันซ้ำ เมื่อใช้โครงการอื่นที่มีฐานเดิมเข้ากันได้ ให้ติดตั้งไฟล์นี้หนึ่งครั้งหลัง migration PM รุ่น v13.6 ส่วนหน้าเว็บต้องนำไฟล์ใน `dist/` ขึ้นโฮสต์เดิมและรีเฟรช ไม่มีการเผยแพร่หน้าเว็บให้จากการแก้ไฟล์ครั้งนี้
